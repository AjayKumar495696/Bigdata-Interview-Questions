2Q : What is the difference between singleton and companion objects in Scala? Write a code for both?
Ans : Every companion object is a singleton object but every singleton object is not a companion object.
      Both singleton object and companion objects are defined using object keyword.

      Singleton Object :
      1) Any object which is declared using object keyword is called as a singleton object.
      2) Its relationship to a class is independent
      3) Which means it does not share a name with a class in the same file
      4) Used for global utility functions, application entry point like main, and configurations.
      5) Does not require a corresponding class.
      6) Example : object Calculator

      Companion Object :
      1) A singleton object which is having the same name as its class name is called as companion object.
      2) Its relationship to a class is paired
      3) Which means it shares the exact same name and resides in the same source file as a class.
      4) Commonly used for factory methods like apply(), and class-related functionality.
      5) Must have a corresponding class.
      6) Example : class Employee & object Employee	
Refer OOP_Concepts.SingletonAndCompanionObject package in scala_codes_ak

6Q : What is the difference between map and flatMap? Write a program for map and flatmap in Scala?
Ans : Map and flatMap are higher order functions in Scala. They used to transforms the collections.
      Map :
      Map is used to apply a function to each element of a collection and returns a new collection where each element of the collection is the result of applying function.
      Syntax : Val myList1 = List(1,2,3,4)
               val doubledList = myList1.map(x=>x*2)
               println(doubledList)
               O/P : List(2,4,6,8)

      flatMap :
      flatMap is also used to apply a function to each element of a collection and returns a new collection but here it flatten the result into a single collection.
      Syntax : val myList2 = List(1,2,3,4)
               val flatMapList = myList2.flatMap(x=>List(x,x*2))
               println(flatMapList)
               O/P : List(1,2,2,4,3,6,4,8)

9Q : What are the different types of inheritance available in Scala? Explain me them? Write a code for each inheritance with example?
Ans : Types of inheritance that Scala support are :
      Single inheritance, Multilevel inheritance, Hierarchical inheritance, Multiple inheritance and Hybrid inheritance.
      Single, Multilevel and Hierarchical inheritance can be achieved by classes in Scala.
      But Multiple and hybrid inheritances are not achieved by classes. These are achieved by traits.
      a) Single inheritance :
         A ---> B
      b) Multilevel inheritance :
         A ---> B ---> C
      c) Hierarchical inheritance :
              ----> B
              |
         A ---|---> C
              |
              ----> D
      d) Multiple inheritance
             A       B
             |       |
             |       |
             ---------
                 |
                 C
      e) Hybrid inheritance
                  A
                 / \
                /   \
               B     C
               \     /
                \   /
                  D

14: Difference between Nil, Null, Nothing and None?
Ans : In Scala, Nil, Null, Nothing, and None serve completely different purposes in the type system and collection framework.
      While they all represent a form of "emptiness" or "absence," they range from concrete values to abstract types.
      Nil :
      It is an empty list
      Ex : List[Nothing]
      Nil is an actual object that represents a List with zero elements.
      Under the hood, its type is List[Nothing].
      Because Scala lists are covariant, Nil can safely stand in as an empty list for any type (e.g., List[String] or List[Int])
      Ex :
      val emptyList: List[Int] = Nil
      val alternative: List[Int] = List() // Equivalent to Nil
      Use case :
      To initialize an empty list or act as the base case for list recursion.

      Null and null :
      It is a trait (Null) and its literal value (null).
      Ex : Null (subtype of all reference types)
      Null is a trait at the bottom of the reference type (AnyRef) hierarchy.
      null is the single concrete instance of that trait.
      It behaves exactly like null in Java.
      It is highly discouraged in idiomatic Scala because it causes NullPointerExceptions.
      It is primarily supported for Java interoperability.
      Ex :
      val badPractice: String = null // Avoid doing this in Scala
      Use case :
      Interoperability with Java. (Idiomatic Scala avoids this).

      Nothing :
      It is a bottom type with zero instances.
      Ex : Nothing (subtype of every type)
      Nothing is a type, not a value.
      It sits at the absolute bottom of Scala's entire type hierarchy.
      There are zero instances of Nothing.It tells the compiler that a piece of code will never terminate normally.
      For example, if a function always throws an exception or enters an infinite loop, its return type is Nothing.
      Ex :
      def crashAndBurn(): Nothing = throw new RuntimeException("System failure")
      Use case :
      Return type for methods that always throw exceptions or crash.

      None : 
      It is an absent optional value.
      Ex : Option[Nothing]
      None is an object used to handle missing values safely.
      It is one of the two children of Scala’s Option[A] type (the other being Some(value)).
      Instead of returning null when something is missing, a Scala function returns None to force the developer to handle the absence safely.
      Ex :
      val userCapitals: Map[String, String] = Map("France" -> "Paris")
      val capital1: Option[String] = userCapitals.get("France") // Returns Some("Paris")
      val capital2: Option[String] = userCapitals.get("Japan")  // Returns None Safely
      Use case :
      Used with Some to safely represent a value that might be missing.

15Q : What is the difference between standard recursion and tail recursion in Scala? Explain me with an example code?
Ans : In Scala, the fundamental difference between standard recursion and tail recursion lies in where the recursive call happens and how the Scala compiler handles memory.
      Standard (Non-Tail) recursion :
      In standard recursion, the recursive call is not the final step.
      The program must return to the current frame to finish a calculation.
      Ex :
      Refer Recursion_Vs_TailRecursion Package in scala_codes_ak
      
      Tail recursion :
      In tail recursion, the recursive call is the absolute last operation the function performs.
      This allows the Scala compiler to optimize the code under the hood by turning it into a fast loop, completely eliminating the risk of a StackOverflowError.
      Ex :
      Refer Refer Recursion_Vs_TailRecursion Package in scala_codes_ak

2Q : Why Scala is Popular among other programming languages?
Ans : 1) Easy to Start :
            -> Scala is high level language so it is closer to other popular programming languages like Java, C, C++.
            -> Thus it becomes very easy to learn Scala for anyone.
            -> For Java Programmers, Scala is more easy to learn.
      2) Contains best features :
            -> Scala contains the features of different languages like C, C++, Java etc.
            -> Which makes it more useful, scalable and productive.
      3) Close integration with Java :
            -> The source code of the Scala is designed in such a way that its compiler can interpret the Java classes.
            -> Also, its compiler can utilize the frameworks, Java Libraries, and tools etc.
            -> After compilation, Scala programs can run on JVM.
      4) Web - Based & Desktop Application Development :
            -> For the web applications it provides the support by compiling to JavaScript.
            -> Similarly for desktop applications, it can be compiled to JVM bytecode.
      5) Used by Big Companies :
            -> Most of the popular companies like Apple, Twitter, Walmart, Google etc. move their most of codes to Scala from some other languages.
            -> Reason being it is highly scalable and can be used in backend operations.
