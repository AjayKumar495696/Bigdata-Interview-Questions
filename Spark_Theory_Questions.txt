1Q : Explain the Spark job architecture?
Ans : Spark job architecture is designed to enable distributed and parallel processing of larger data sets on a cluster of machines.
      The architecture has mainly 4 components.
      Driver program, Spark Context object, Cluster manager and Worker nodes.
      1) Driver Program :
         It coordinates the job's execution and it will create Spark context object.
      2) Spark Context Object :
         It manages the distribution of data and the execution of tasks across the cluster.
      3) Cluster Manager :
         It will allocate resources to the Spark job. And it is also called as Resource Manager.
      4) Worker Nodes :
         These execute the tasks using the executor.

2Q : What is the difference between repartition and coalesce? Write a syntax for repartition and coalesce?
Ans : Repartition and Coalesce are two operations in Apache Spark to change the number of partitions of a dataset.
      Repartition :
      1. It will increase or decrease the number of partitions of a dataset.
      2. Repartition is slower as it performs full shuffling the data.
      3. Repartition is costly.
      Syntax :
      val repartitionedDF = df.repartition(numPartitions)
      val repartitionedRDD = rdd.repartition(numPartitions)

      Coalesce :
      1. It will decrease the number of partitions of a dataset.
      2. Coalesce is faster as it performs partial shuffling the data or some times no shuffling the data.
      3. Coalesce is cheaper and more efficient than Repartition when decreasing the number of partitions.
      Syntax :
      val coalescedDF = df.coalesce(numPartitions)
      val coalescedRDD = RDD.coalesce(numPartitions)

4Q : What is Cache and Persistence in Apache Spark? What are the different storage levels available in Persistence?
Ans : Caching :
      It will store the intermediate results in memory so Spark can quickly retrieve them without recomputing the
      entire lineage when the same data is needed again.

      Persistence :
      Where as Persistence, it will store the intermediate results in different storage levels.
      These are Disk or Memory or combination of both.
      Different storage levels in Persistence are :
      DISK_ONLY
      MEMORY_ONLY
      MEMORY_ONLY_SER
      MEMORY_AND_DISK
      MEMORY_AND_DISK_SER

6Q : What is the difference between RDD, DataFrame and Dataset?

      1. RDD released version is 1.0

      1. DataFrame released version is 1.3

      6. It supports Java, Scala, Python and R programming languages.
      Dataset :
      1. Dataset released version is 1.6
      2. Dataset is the combination of both RDD and DataFrame.
      3. It supports structured and un-structured data.
      4. Compile time type-safety is available here.
      5. Query optimization is happened through the catalyst optimizer.
      6. It supports Java and Scala languages only.

11Q : What is the difference between transformations and actions? Give some examples?
Ans : Transformations :
      -> Transformations are operations that create a new RDD from existing one.
      -> They are lazy, means they do not immediately execute when they called.
      -> Instead, they build up a logical execution plan that only gets executed when an action is called.
      Ex :
      map, flatMap, filter, union, select, join, groupByKey, reduceByKey, distinct, repartition, sort

      Actions :
      -> Actions are operations that trigger the execution of the transformations and return a result to the driver
      program or write data to an external storage system.
      Ex :
      collect, count, reduce, first, take

12Q : Difference between Narrow and Wide transformations?
Ans : Narrow transformations :
      -> Narrow transformations are those where each input partition contributes to exactly one output partition.
      -> This means that there is no need to shuffle data across the cluster, making these transformations are more efficient.
      Ex :
      map, flatMap, filter, union, select
      Wide transformations :
      -> Wide transformations involve shuffling data across partitions, where multiple input partitions may contribute to a
         single output partition.
      -> This requires a data exchange between nodes in the cluster.
      Ex :
      join, groupByKey, reduceByKey, distinct, repartition, sort

13Q : What is Shuffling?
Ans : Shuffling in spark is a process that involves redistributing the data across different partitions and nodes in a cluster.
      It occurs when the data needs to be reorganized to group related records together, during operations like groupBy, reduceByKey, join or distinct.

14Q : Difference between CSV, Parquet and ORC file formats?
Ans : CSV : CSV is a plain text format where each line represents a record and each field within a record is separated by a
            delimiter comma. It does not have schema or metadata. The schema needs to be defined by the application.
      Parquet : It is a columnar storage file format designed for efficient data processing. These are self describing and they 
                store schema along with the data.
      ORC : It is another columnar storage format similar to parquet designed for efficient storage and processing of large datasets.
            ORC files also stores the schema with the data.

16Q : What is a DAG?
Ans : DAG means Directed Acyclic Graph.
      It allows Spark to break down a large-scale data processing job into smaller, independent tasks that can be executed in parallel,
      optimize the job execution, achieve fault tolerance, reuse intermediate results, and provide a visual representation of the logical execution plan.

17Q : What is fault tolerance in Apache Spark?
Ans : Fault tolerance is the Spark framework's ability to seamlessly recover from failures such as worker node crashes, executor loss, or network drops.
      And it complete the data processing jobs with zero data loss.
      Older systems like Hadoop MapReduce achieve reliability by writing the data to disk but Spark achieve fault tolerance through in-memory tracking.

18Q : What is lazy evaluation in Spark?
Ans : Lazy evaluation is one of the feature of Spark.
      It delays the execution of data operations until an action is explicitly called.
      Which means it holds off on executing transformations until an action is executed.
      For Ex : if we want to run a transformation like df.filter(), Spark won't filter our dataframe until we run an action called df.show()

7Q : What are the different optimization techniques in Apache Spark?
Ans : Apache Spark provides a wide range of optimization techniques to improve the performance of data processing of larger datasets.
      Optimization techniques :
      1) Caching :
	  -> Spark provides caching mechanism that allows users to cache rdds in memory.
	  -> This improves the performance of iterative algorithms that reuse the same data multiple times.
	  
      2) Partitioning :
	  -> Spark allows users to partition RDDs based on a specific key, which can help optimize operations.
    
      3) Broadcasting :
          -> Spark provides broadcasting mechanism which allows users to send read-only variable to all the nodes.
          -> This can improve the performance of operations that require the use of a lookup table or other reference data.

      4) Repartitioning and Coalescing :
          -> Repartitioning and Coalescing are techniques that can be used to optimize operations by reducing the number
             of partitions or redistributing the data across partitions.

      5) Predicate Pushdown :
          -> Spark provides predicate pushdown technique which allows users to push filters down to the data storage layer.
          -> This can reduce the amount of data need to be read from disk and improve the performance.

      6) Data Serialization :
          -> Spark provides a range of serialization formats that can be used to optimize the performance of data processing
             by reducing the size of data transmitted  between nodes.

      7) Shuffle Optimization :
          -> Spark provides a range of techniques to optimize shuffles, which are operations that require data to be shuffled across nodes in a cluster.
	  -> These techniques include pipelining, sorting and combining data.

27Q : Explain the Spark job execution flow?
Ans : 1) Application Submission :
         When we submit a Spark application using spark-submit, the Driver starts and connects with the Cluster Manager.
      2) Job and Stage Creation :
         Each action (e.g collect(), save()) triggers a job.
         A job is divided into stages, based on shuffle boundaries.
         Each stage contains tasks.
      3) Task Scheduling :
         The driver schedules tasks to executors based on data locality.
         Tasks run in parallel across the cluster.
      4) Execution and result :
         Executors process the tasks and return results to the driver.
         The driver then assembles the final output of the job.
